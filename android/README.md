# FocusFlow — Android (Capacitor)

Native Android shell for the FocusFlow PWA via [Capacitor 6](https://capacitorjs.com).
The entire web app is bundled into the APK/AAB (`app/src/main/assets/public`,
regenerated by `npx cap sync android`), so **the app works fully offline** — the
WebView serves the bundle from a local origin; no network is ever required.

## Prereqs

- Node 18+ and JDK 17
- Android SDK: platform `android-34`, build-tools `34.0.0` (Android Studio installs these)

## Build

```bash
# from the repo root
npm ci
npx cap sync android          # copies app/ → android/app/src/main/assets/public
cd android
./gradlew assembleDebug       # → app/build/outputs/apk/debug/app-debug.apk
./gradlew bundleRelease       # → app/build/outputs/bundle/release/app-release.aab
./gradlew assembleRelease     # → app/build/outputs/apk/release/app-release.apk
```

Open `android/` in Android Studio for the full IDE experience (sync Gradle, run on device/emulator).

## Signing (release)

`app/build.gradle` reads `android/keystore.properties` (**gitignored**). Generate your
own release key — never commit it:

```bash
keytool -genkeypair -keystore keystore/focusflow-release.jks -alias focusflow \
  -keyalg RSA -keysize 2048 -validity 10000

cat > keystore.properties <<EOF
storeFile=keystore/focusflow-release.jks
keyAlias=focusflow
storePassword=YOUR_PASSWORD
keyPassword=YOUR_PASSWORD
EOF
```

Without `keystore.properties`, `bundleRelease` still succeeds and produces an
**unsigned** AAB (fine for CI; Play Console re-signs via Play App Signing).
For CI-produced **signed** artifacts, store the keystore as a base64 secret and
materialize `keystore.properties` in the workflow.

## App configuration

| Item | Value |
|---|---|
| App ID / package | `com.focusflow.app` |
| Version | `1.0.0` (versionCode 1) |
| minSdk / target / compile | 22 / 34 / 34 |
| Launcher icon | Adaptive icon (navy `#0B0E1A` background + Flow Ring foreground cutout), legacy + round PNGs, all densities |
| Splash | `Theme.SplashScreen` (Android 12+ shows branded adaptive icon on navy) + bitmap splashes for pre-12 |
| Permissions | `INTERNET` (bridge), `POST_NOTIFICATIONS`, `SCHEDULE_EXACT_ALARM`, plus plugin-provided `RECEIVE_BOOT_COMPLETED` / `WAKE_LOCK` |
| Notification channel | `focusflow_phases` (created in `MainActivity`) — exact phase-end alerts scheduled while running, fire even if the app is killed |

## Verifying a build

```bash
apksigner verify --print-certs app-release.apk
aapt dump badging app-release.apk | grep -E "package|launchable-activity|uses-permission"
adb install app/build/outputs/apk/debug/app-debug.apk
adb shell monkey -p com.focusflow.app -c android.intent.category.LAUNCHER 1
adb shell pidof com.focusflow.app   # process alive ⇒ launch OK
```

CI (`.github/workflows/android.yml`) runs exactly this on every push, including a
booted-emulator launch test on API 34.

## Notes & limitations

- **Background timers:** Android suspends the WebView when backgrounded; the
  timestamp engine catches up on resume, and the *scheduled local notification*
  (created when a phase starts) still fires at the right moment. Foreground
  behavior is identical to the PWA.
- The Web Notification API is unavailable in WebViews — `notify.js` bridged to
  Capacitor LocalNotifications; browsers keep the original behavior.
- Landscape is locked off (`screenOrientation="portrait"`), matching the PWA's
  portrait-primary design.
